## Tasks

1. **Archived chevron.** The sidebar's Archived row gets an expand/collapse chevron in the same right-hand column as the client chevrons and the Notes `+` (sprint 049 aligned those at the right edge; same box size, same right inset). Keep `aria-expanded`. (Owner said "left hand chevron": read as the chevron in the left-hand sidebar, aligned with the contract chevrons; record under Deviations if you find a reason to read it otherwise.)
2. **Settings into the scrolling list.** Remove the fixed footer "Settings" link; Settings becomes a row in the scrolling sidebar content in the same list/style as Archived and Trash (icon + label like Trash). Above the timer there is then nothing but the timer widget. Phone and desktop.
3. **"Notes" heading opens all notes.** Rename the "Contracts" heading to "Notes" (keep the `+` New contract on its right; its label stays "New contract"). Clicking/tapping the heading opens a combined list of all the user's notes across every active and archived contract, newest first by last modified (note: the same time the list rows show), with no pinned section and pins not floated. Rows show the client/contract (like the client view's combined list does) so the user can tell them apart. It is a real navigation step with its own URL (fits sprint 050's back/forward; label "All notes"), survives reload, selected state on the heading. Reuse the client combined view machinery where possible. If `GET /api/notes` needs a way to list all notes, add an explicit opt-in (e.g. `?all=true`) rather than changing the current 400 for no filter; keep it paginated or capped sensibly if the list endpoint has a convention.
4. **Save status: "Saved" / "Saving".** Replace the current saved/unsaved wording with "Saved" / "Saving" (keep an error state, if one exists, distinct). Give the indicator a fixed width (fits the longer label plus padding) and a pill with green (saved) / amber (saving) tint so neither state shifts the header line; no overflow or line wrap as the user types at 320 px, 390 px and desktop. Keep `data-testid="save-status"` and its `data-status` values so tests keep working (or update tests consistently).
5. **Move and Export without chevrons.** In the note editor's header bar, the Move and Export buttons lose their dropdown chevrons (menus still open the same way, `aria-haspopup` stays).
6. **Copy the note code.** Clicking/tapping the note code (e.g. `INTL.20261104.0042`) in the note heading copies it to the clipboard, with brief confirmation ("Copied" tooltip/flash, accessible via `aria-live`), cursor pointer, and a title "Copy note code". Works in Safari/WebKit (PWA) and the Tauri webview; fall back gracefully if the clipboard API is refused.

7. **Owner change (2026-11-05): no `+` by the heading.** Remove the sprint 049 `+` (New contract) next to the sidebar heading; new contracts are made in Settings. The Archived and client chevrons still share one right-aligned column. The no-contracts hint points to Settings; Settings → Clients must still create clients and contracts; update the 049 Playwright test; drop the sidebar's `ContractCreateModal` wiring.
8. **Owner change (2026-11-05, reported as a bug): no search box in the note list.** Remove "Search all notes" from the middle panel; search lives only in the top bar (`GlobalSearchField`, the phone's search icon). Delete `note-list-search.svelte.ts` and its wiring; keep `/api/notes/search` if anything else uses it; move Playwright coverage to the top-bar search.

### Done

2. **Settings into the scrolling list.** The fixed "Settings" footer is gone; Settings is a row under Trash in the same muted icon + label style (`SidebarUtilityLinks.svelte`, which replaces `SidebarTrashLink.svelte`). Below the scrolling list there is only the timer widget (desktop and phone).
3. **"Notes" heading opens all notes.** The heading reads "Notes" and is a button (`sidebar-notes-heading`, `aria-current="page"` and blue while shown) that pushes `/notes/all`: a new route kind `all` (`/notes/all`, `/notes/all/<contract>/<note|new>`) built like the client view, so notes open inside it, closing returns to it, it survives reload and is a Back/Forward step labelled "All notes" (also the phone title and the page title "Chronolog · Notes · All notes"). New Note there opens a menu of every active contract, each named "Client · Contract". Data: `dataService.getAllNotes()` → `GET /api/notes?all=true` (explicit opt-in; no filter is still 400; `all=true` with `contractId`/`clientId` is 400; ordered by `updatedAt desc` server-side), also in the delegating and offline data services (queued offline creates are projected in).
4. **Save status "Saved" / "Saving".** `SaveStatusIndicator` is a pill of fixed width (`w-[4.75rem]`): "Saved" green, "Saving" amber (also while a change waits for its debounce, i.e. `unsaved`), "Draft" grey for an unsaved new note. `error` and `conflict` stay distinct: red pills with their existing wording. `data-testid="save-status"` and every `data-status` value are unchanged. Labels in `save-status-display.ts` (unit-tested). Playwright checks that the header, the pill and the note code have identical bounding boxes in Saving and Saved at 1280, 390 and 320.
5. **Move and Export without chevrons.** "Move" and "Export" lost their `▾`; both now carry `aria-haspopup="menu"` and `aria-expanded` (they had neither before).
6. **Copy the note code.** `NoteCodeCopyButton.svelte`: the code is a button (cursor pointer, title "Copy note code"); a click or tap copies it with `copyText` (`$lib/utils/copy-text.ts`: Clipboard API, then a hidden-textarea `execCommand('copy')`, never throws). A "Copied" bubble floats under the code for 1.5 s (absolutely placed, the line doesn't move) and a polite live region announces it; if both ways are refused it says "Couldn't copy" and selects the code for a manual copy. The code no longer truncates (`flex-shrink-0`); the client/contract label beside it truncates instead, which keeps the full code readable at 320 px.
7. **No `+` (owner change).** The `+` and its `ContractCreateModal` wiring left the sidebar (it also no longer loads `/api/clients`). The sidebar's no-contracts hint now links "Settings → Clients and contracts"; `FirstRunNotice` already pointed there. Settings → Clients still has Add Client and, on a client, Add Contract (Playwright checks both). The 049 test now checks there is no `+` and that the client chevrons sit at the group's right edge and still collapse.
8. **No list search box (owner change).** "Search all notes" is gone from the note list; `note-list-search.svelte.ts` and `NoteSearchResults.svelte` (used only there) are deleted. `notes-navigation.spec.ts`'s "search result → other contract" step now goes through the top-bar search (type, Enter, click the hit). `/api/notes/search` stays: the `[[` wiki-link suggestions and the time entry description's link input use it.

### Deviations

- "Left hand chevron" read as the chevron in the left-hand sidebar, aligned with the client chevrons (right-hand column), as the spec suggested.
- `ContractCreateModal.svelte` was deleted, not kept: Settings creates contracts with its own form on the client page and nothing else used the modal (the spec says keep it only if Settings used it).
- `dataService.searchNotes` (and its offline fallback) is now unused by the UI; kept, since it is part of the data service interface and tests, and costs nothing. Say if it should go.
- The all-notes view honours the list's existing sort toggle (Modified ↓ / Created ↓; default Modified), so "newest first" follows the time the rows show, as the spec's note asks. The API's `all=true` order is always last modified.
- `GET /api/notes?all=true` is not paginated or capped: the list endpoint has no pagination convention (the client and contract lists aren't capped either).
- A new-note draft's pill reads "Draft" (was "Not saved yet") so it fits the fixed width; its tooltip says "Not saved until you type".
- The conflict and error pills are sized to their message (not the fixed width): they stop saving and are rare, and the conflict wording is asserted by `notes-conflict.spec.ts`.
- Move / Export gained `aria-haspopup="menu"` + `aria-expanded` (the spec assumed they had them); the menu items are still plain buttons, so tests that click them by role keep working.
- Tests that waited for the "Contracts" text (`smoke`, `offline-behavior`) now use `sidebar-notes-heading`; `navigation-journeys` and `notes-navigation` click "Move" by exact name (no `▾`). The note code keeps a `span.font-mono` inside the button, which `openNoteId()` reads.
