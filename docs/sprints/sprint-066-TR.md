- **TT-04** Phone: presets (sharing the row's width), From / To side by side, the `TotalTimeContractsRow` ("Contracts · N selected", filter icon, chevron), then the total and By contract. The ISO range caption is gone (desktop too). The page scrolls.
- **TT-05** `TotalTimeContractSheet`: a tall sheet over the dimmed results; Contracts with All | None; the same `TotalTimeContractList` over the same selection (no Apply copy); an anchored footer with "N selected" (the only count in the sheet) and Done, bottom safe area kept; the footer is a flex sibling, so it never covers the last row. ## Not met / notes

- **TT-13 resize across 768 px**: `AppShell` swaps its phone and desktop DOM branches at 767/768 px, remounting the timesheet and with it any open modal (Total time and Add entry alike), so crossing that width closes the modal. Pre-existing and outside this presentation-only sprint; within the modal the layout logic keeps one selection and closes the sheet when wide. A fix would lift the modal's open state and filters above `AppShell`'s branches.
- The contract name is never split into name and context (no reliable field); the selector shows the name only, the breakdown adds the client.
- Native date inputs keep the browser's locale format (the crops' "9 Nov 2026" is illustrative).

## Follow-up fixes (after v1.7.1, branch `total-time-fixes`, 2026-11-11)

The owner, on a real iPhone (Safari PWA): "on mobile you can still scroll when the modal opens and that leads to unexpected behaviour, and the inability to close the contract sub modal. Also, the two date boxes collide horizontally."

- **Background scroll / sheet that would not close.** iOS Safari ignores `overflow: hidden` on the body for touch scrolling and rubber-bands the document under a fixed overlay, which could carry the sheet's footer and backdrop out of reach (headless WebKit does not reproduce it). New `src/lib/utils/scroll-lock.ts`: `lockBodyScroll()` pins the body (`position: fixed; top: -scrollY; width: 100%; overflow: hidden`) and restores the scroll position on unlock, reference-counted so the sheet's lock inside the modal never releases the page early. Used by TotalTimeModal, TotalTimeContractSheet and AddTimeEntryModal (same class of bug). The overlays are `touch-action: none`; only the inner scrollers pan (`pan-y`, the preset row `manipulation`), each with `overscroll-behavior: contain`, so a drag on the header, the sheet's handle or footer never reaches the page. The sheet is now `position: fixed` over the same visual-viewport box as the modal (it covers the whole screen, header included); Done (pinned footer), a backdrop tap and Escape close it.
- **From / To collided.** iOS gives a native date input an intrinsic width it will not shrink below and ignores `width` until the appearance is reset. At phone width the inputs now have `display: block; width: 100%; min-width: 0; appearance: none` (and `-webkit-`), a 44 px minimum height (an empty reset date input collapses on iOS) and a left-aligned value, in a scoped style; the labels are `flex-1 min-w-0` with the existing gap. The font stays 16 px (no zoom on focus); at 320 px both fit, so no smaller type was needed. Desktop keeps the native look.
- **Tests.** `scroll-lock.test.ts` (2: lock and restore, reference counting). Playwright `@iphone`: the body is locked while the modal is open and released on close, the timesheet's scroll position does not move while the modal or sheet is scrolled, the overlay is `touch-action: none` and the scroller `pan-y`; the sheet's backdrop covers the whole screen, scrolled to its end Done stays fully visible and closes it, the modal's lock outlives the sheet's; From and To inside the modal, on one line, with a gap and at least 16 px type at 320 and 375 px wide (iphone-se, iphone-15). Not provable headlessly: the iOS rubber-band itself; owner check on a real iPhone recommended.
