## Bug recorded (not fixed: older than this branch and not contained)

**Editor, Chromium only: Enter (or Shift+Enter) at the end of a list item sends the caret to the top of the note.** Text typed next goes into the H1. For example, the Kick-off agenda note's title became "See [[Kick-off agenda", and autosave keeps that title. Steps: open a note that has a bullet or task list, click the end of an item, press Enter, type. In WebKit (Safari, and the Tauri macOS shell) the text lands in the right place. In Chromium a probe showed the text in the right paragraph straight after typing, then in the heading within about 0.5 s. With a timer running, the same happened after Enter at the end of a plain paragraph; without a timer it did not. That points at something asynchronous that resets the ProseMirror selection. The candidates are a content re-sync after save and the timer's re-renders; `note-scroll-memory` restores only on history returns, so it is not the cause. No editor file has changed since v1.5.0 apart from toolbar classes, so this is probably live too. It also explains the old checkpoint B/C editor-picker screenshot, whose text sat in the heading as well. **Confirm by hand in Chrome before deciding.** No test covers Enter inside lists in Chromium.
