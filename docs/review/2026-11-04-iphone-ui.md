# iPhone UI review — 2026-11-04 (sprint 047-QA)

Every main journey walked in Playwright WebKit with its iPhone device descriptors (viewport, touch,
mobile user agent, device scale): **iPhone SE (3rd gen)** 375×667, **iPhone 15** 393×659 (Safari's
visible area of an 852-point screen), **iPhone 15 Pro Max** 430×739, portrait, plus **iPhone 15
landscape** 734×343. The installed Playwright is 1.60.0; its descriptors were checked against the
Playwright device/emulation docs. Screenshots are in `docs/review/screenshots/sprint-047/`:
`<project>-NN-<screen>.png` from `e2e-playwright/iphone-journeys.spec.ts`, `before/` and `after/`
for the fixed issues (scaled to 375 px wide), and `<project>-00-device-key-gate.png` from a one-off
run against a second dev server with `DEVICE_ACCESS_KEY_HASH` set.

## Method

- Fresh `qa-047-*` users on the shared dev database, data seeded through the API (a client with two
  contracts, two notes with a task list and a wiki-link, an entry today).
- A scratch script took a screenshot of every screen at every size and measured, on each screen and
  after opening each form, menu and modal: sideways overflow, fields under 16 px, and tap targets
  under 44×44. Every screenshot was looked at, before and after the fixes.
- Journeys: device-key gate; sign-in (password; the 2FA sign-in through
  `two-factor-login.spec.ts` on the iPhone project); first-run notice; the week, Today, add / edit /
  delete an entry, timer start / adjust / stop / discard, week status menu; sidebar, client view,
  collapse, pin; note list, editor (toolbar, task lists, wiki-link list, find, Move / Export menus),
  linked entries, delete and Undo, trash; global search; Settings (clients, contracts, deliverables,
  Archive / Activate, 2FA, API tokens); offline banner.
- Afterwards the whole Playwright suite was run once on the iPhone 15 project
  (`PLAYWRIGHT_IPHONE_ALL=1`), see the end of this document.

## Findings

Severity: **High** blocks or badly degrades a journey on a phone; **Medium** works but is hard or
error-prone with a finger; **Low** cosmetic.

Checked and fine: no sideways page scroll on any screen at 375–430 px after the fixes (the 046 search
layout and 043 linked entries hold); the first-run notice wraps cleanly; the week status menu, timer
sheet, New Contract modal, 2FA and API token pages fit; the note toolbar scrolls sideways inside
itself and its last button is reachable; task-list boxes are 20 px but sit in full-width rows;
device-key gate field is 16 px and unlocks; Pro Max landscape (814×380) gets the tablet two-panel
layout as designed in 026-CL.

## Backlog proposals (deferred)

1. **Client order on touch.** Sort Settings → Clients by the user's client order (the sidebar's,
   `client-order` queries) and give each active row Move up / Move down like contracts have, using
   `PATCH /api/clients/reorder`. Medium: changes the clients page load and its tests (044 colour hint
   and 041 Archive specs use that page).
2. **Phone title bar with a running timer.** Drop the context title when the timer pill shows, or move
   the pill into the bottom bar; let the running-timer sheet collapse to one line. Small.
3. **Contract move arrows** at 44 px on touch (one class in `ContractRow.svelte`). Trivial; left so
   the row layout can be redone with item 1.
