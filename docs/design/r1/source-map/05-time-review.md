## (a) What exists today

### 1. Week model

- **Hand-rolled ISO 8601 helpers, no library.** `iso-week.ts:1-6` documents ISO (Monday start, week 1 contains the first Thursday). `getIsoWeekNumber` (`iso-week.ts:9-17`) and `getIsoYear` (`:20-25`) use the nearest-Thursday method in local time; `getMondayOfIsoWeek` (`:31-42`) uses 4 January; `getMondayOfWeek` (`:45-51`) gives the Monday of any date.
- **A week is identified by its Monday date (`YYYY-MM-DD`) on the client** (`TimeEntriesPanel.svelte:148,151`; `navigation.selectedWeek`). The URL uses an ISO key `/time/2026-W45` (`stores/navigation-routes.ts:5,44-57`, which rejects a W53 that rolls into the next year, `:56-57`). `/api/me` reports `isoWeek` via `utils/local-calendar.ts:31,56`; the CLI parses `2026-W45` keys with its own copy of the ISO rule (`cli/lib/dates.mjs:21-35`).
- **Label:** `Week {getIsoWeekNumber(weekStart)} · {formatWeekRange(weekStart)}` (`WeekStrip.svelte:41,78-80`), e.g. "Week 45 · Nov 2-8, 2026"; cross-year ranges show both years (`iso-week.ts:102-105`). The same ISO number is used in the tab title (`routes/(workspace)/+layout.svelte:31`), history labels (`layout/navigation-labels.ts:22,49`) and older-week headings (`TimeEntriesPanel.svelte:480-483`).
- **Paging:** ◀/▶ shift by 7 days (`TimeEntriesPanel.svelte:196-200,358-368`) and lazily load the week (`:231-247`). Prev/next buttons show "Week N" from `sm` up, computed by arithmetic, not from dates: `prev = n>1 ? n-1 : 52`, `next = n<52 ? n+1 : 1` (`WeekStrip.svelte:42-43,77,96`). **This mislabels 53-week years** (see c/O05). Initial load fetches the current week and three before (`TimeEntriesPanel.svelte:218-228`); "Show the week before" appends older weeks under the selected one, showing only days with entries (`:249-262,477-500,548-556`).
- **Today:** button disabled on the current week (`WeekStrip.svelte:83-91`); calls `navigation.showTimeEntryDay(today)`, which selects the week, scrolls today's section to the top and rings it blue for 2.5 s (`TimeEntriesPanel.svelte:100-106,515`).
- **Weekly status:** `WeekStatusMenu.svelte` pill + `role="menu"` of three `menuitemradio` options (`:8-12,93-116`), arrow keys/Escape/Tab/click-outside (`:54-75`). Hints: "Still logging time", "Ready to review", **"Sent to the client"** (`:11`). Colours: stone / amber / emerald (`:26-35`). Change → `handleStatusChange` → `dataService.updateWeeklyStatus(isoYear, isoWeek, status)` (`TimeEntriesPanel.svelte:279-293`) → `POST /api/time-entries/weekly-statuses` (`fetch-data-service.ts:214-216`). Local state updates only after success; **a failure is only `console.error`ed, no UI** (`TimeEntriesPanel.svelte:290-292`). Not queued offline (offline service does not override it). No side effect beyond the upsert (`weekly-statuses/+server.ts:41-65`, `queries/weekly-statuses.ts:28-57`).
- **Storage:** `weekly_statuses(user_id, week_start, year, week_number, status)`, unique on `(user_id, year, week_number)` (`server/db/schema/weekly-statuses.ts:4-24`). Validation: year 2000-2100, week 1-53, status in the three values (`weekly-statuses/week-input.ts:6,21-51`). `GET /api/time-entries/weekly?weeks=<mondays>` reads status by ISO year/week of each Monday (`weekly/+server.ts:24-31`); `GET .../weekly-statuses?weeks=2026-W45` serves the CLI.
- **First partial week today:** there is none. Weeks are always full Mon-Sun and may span years. 29 Dec 2025-4 Jan 2026 is "Week 1" of 2026 (status row 2026/1). 1-3 Jan 2027 sit in "Week 53" of 2026 (status row 2026/53; asserted in `local-calendar.test.ts:12`).

### 2. Layout

- **Structure:** column flex; `FindBar`, then `WeekStrip` (outside the scroller), then the scroller `data-testid="timesheet-scroll"` holding all seven days of the selected week, future days included, Mon→Sun (`TimeEntriesPanel.svelte:174-175,502-558`).
- **Order:** server orders by `date`, `start_time asc nulls last`, `created_at` (`queries/time-entries.ts:104`); grouped by date into 7 `DayGroup`s with totals (`queries/time-entries-weekly.ts:22-53`). **Chronological, never regrouped by client.** Duration-only entries sort after ranged entries of the same day.
- **Week strip:** `sticky top-0 z-10`, static when viewport height ≤500px (`WeekStrip.svelte:69`). 7-column grid of buttons: weekday abbreviation, day number, compact total (`2h15`, en dash for zero) (`:103-116`, `duration.ts:168-176`), and a 1.5px-tall **rounded** bar with one segment per client, ordered by first appearance, width = share of the day's minutes, coloured by client palette index (`WeekStrip.svelte:118-125`, `week-strip-segments.ts:28-57`). Today's cell: amber fill + amber bottom border (`:111`). Right column: week total and the status pill (`:131-134`). Weekday and date are on two lines today, not one.
- **Day headings:** `h2` with `formatDayHeader` ("Friday, Nov 6"), a "Today" pill on today, a "+" add button (hidden while the row is open), day total on the right when >0 (`TimeEntriesPanel.svelte:417-442`). **Not sticky.** Today's section is a tinted amber block (`-mx-3 rounded-lg bg-amber-50/60`, `:409`), not a brown bar. Heights are implicit (text-sm line + `mb-1`).
- **Add entry:** "+" in the heading (`data-add-entry`, 44px on coarse pointers, `:426-434`) and, for an empty day, a dashed "No entries · + Add" box (`:463-472`). Both toggle `NewEntryRow` directly under the heading, above the entries (`:444-450`). Several days can have rows open at once (`expandedAddEntry` map, `:143`).
- **Day click:** `scrollDayToTop(date,'smooth')` sets `scrollTop` to the section's top minus 8px (`:42-50,370-372`); it does not filter. Because the strip is outside the scroller, no sticky offset is needed today. `scrollTop` is used instead of `scrollIntoView` to keep the first Tab in the sidebar (sprint 025, `:37-41`).
- **Scroll memory:** per week, the top visible day and offset are stored in the navigation store and restored on return (`:52-136`).
- **Phone:** the same component. Differences are only responsive classes: tighter padding, prev/next numbers hidden below `sm`, `pointer-coarse` 44px targets, NewEntryRow fields in a 2-column grid with the contract on its own row (`NewEntryRow.svelte:143-146`), and a footer `TimerWidget` when no sidebar timer is mounted (`TimeEntriesPanel.svelte:187,560-565`). Card layout does not reflow on phone.

### 3. Entry row (`TimeEntryCard.svelte`)

- Card: rounded, stone border, **3px left border in client colour** (`:363`, `client-colors.ts:20-59`, 8 Tailwind colours by `clientColorIndex`). No contract pattern/motif exists anywhere in the row.
- Left column: (1) description as the hero, clamped to 3 lines with Show more/less (`:405-440`), placeholder "What did you work on?" when empty (`:430`); "Formerly: …" lines muted below (`:441-443`); (2) client dot + "Client / Contract" (`:465-473`, `contract-label.ts:5-7`); (3) "Deliverable > Work type" indented (`:510-516`).
- Right column: duration (`formatMinutes`, "2h 15m") and, under it, the range `09:00-11:15` only when both times exist (`:535-563`, `duration.ts:182-187`). **A duration-only entry shows the duration alone; no range is invented.**
- **Missing detail:** with neither deliverable nor work type, an italic "Add deliverable…" is always shown if the contract has deliverables, otherwise only on hover/focus (`:517-527`). A deliverable without a work type shows only the deliverable; no cue. No missing-detail flag at entry level.
- Delete × top-right (hover/focus-within/touch) with inline Yes/No confirm (`:372-396`); Attach note under it (`:398-401`); offline `OutboxMarker` (`:367-370`).
- **Wiki-links:** `[[noteId]]` or `[[noteId|label]]` rendered by `WikiLinkRenderer` as inline indigo underlined `<button>`s showing the note title (ID until fetched), trashed notes struck through with a restore prompt (`WikiLinkRenderer.svelte:10-23,73-93`). Click → `stopPropagation` → `openNoteFromEntry` → notes mode with editor focus (`TimeEntriesPanel.svelte:336-348`). **These link buttons are nested inside the description `<button>`** (`TimeEntryCard.svelte:416-432`).

### 4. Inline editing semantics (TR-06 / O11)

Every field is a `<button>` that swaps in an editor on click (no hover-only entry; works on touch). Each save is an independent `PUT /api/time-entries/:id` with only the changed fields (`TimeEntryCard.svelte:143-153`, `fetch-data-service.ts:206-208`), then `onUpdated` → `refreshWeeks()` refetches **all loaded weeks** (`TimeEntriesPanel.svelte:269-277,457`).

| Field | Editor | Commit | Cancel | Focus after |
| --- | --- | --- | --- | --- |
| Description | `WikiLinkInput`, single-line `<input type=text>` (`WikiLinkInput.svelte:157-166`) | Enter, or **blur** (150 ms delayed, `:147-153`); skipped if unchanged (`TimeEntryCard.svelte:298-304`) | Escape sets a flag so the delayed blur does not save (`:306-317`) | back to description button (`:310,315`) |
| `[[` picker inside it | absolute dropdown `z-50 w-72` (`WikiLinkInput.svelte:169`), 200 ms debounced `/api/notes/search` | Enter picks a result | Escape closes the dropdown only (`:137-141`) | stays in input |
| Time | `DurationField` (`timer/DurationField.svelte`) | Enter or **blur** if valid; unchanged text not sent (`TimeEntryCard.svelte:163-179,200-204`) | Escape (`:181-198`) | time button |
| Contract | native `<select>` (`ContractSelect.svelte:58`) | **on change, immediately** (effect `:216-220`); always clears deliverable+work type (`:227-244`) | Enter/Escape/focus-out just close (`:246-252,451-455`) | contract button, or the deliverable pickers when a chain was cleared, with an amber notice (`:238-243,505-509`) |
| Deliverable / work type | two native selects + Done (`:479-504`) | **each pick saves immediately**; deliverable change clears work type (`:270-278`) | Enter/Escape/Done close (`:280-285`); there is nothing to revert | deliverable button |

- Parser (`duration.ts:51-151`): decimal hours, `h`/`m` forms, bare minutes, `H:MM`, ranges `9-10:30` (en dash ok); rejects empty, zero, >24h, end ≤ start; warns >12h. Editing pre-fills the range if present else compact duration (`:190-198`); a duration-only save sends `startTime:null,endTime:null` (`TimeEntryCard.svelte:174-178`). Ranges cannot cross midnight.
- **Errors:** invalid time keeps the editor open with a red message under the field (`DurationField.svelte:76-81`); server/network failures show one `role="alert"` line on the card, "Couldn't save: …" (`TimeEntryCard.svelte:80,150,530-532`, `timer/save-error.ts`). The editor has already closed by then; the typed value is not restored.
- **Conflicts:** time-entry PUT has **no version check and no 409** (`api/time-entries/[id]/+server.ts:25-80`); last write wins online. 409s exist only for notes, timer and duplicates. Offline, conflicts are detected at replay by base-vs-server field-group comparison and held (`offline/outbox-replay.ts:326-350`, `outbox-merge.ts:77-101`).
- **Reflow:** contract/deliverable/work-type pickers are native selects (popup does not reflow), but swapping the label for a select, the Done button and the contract-change notice change row height. `DurationField` adds a line below the input for the preview "= 1h 30m", warning or error (`DurationField.svelte:76-81`), growing the card while typing. The wiki-link dropdown is absolute and does not reflow. The description input is single-line, so a wrapped 3-line description collapses to one line while editing.
- **NewEntryRow differs:** an explicit form, **no blur-to-save**; Save/Retry button or Enter in any field submits; Escape or Cancel discards everything (`NewEntryRow.svelte:84-126,203-223`). Labelled fields; inline errors "Pick a contract", parser hint, "Couldn't save" (`:37-40,88-91,157-159,205-207`). Contract change resets the chain (`:57-65`). Left border takes the chosen client's colour (`:72-82`). On save: row closes, weeks refresh, focus goes to the new card (`TimeEntriesPanel.svelte:312-316`); on cancel focus returns to the day's "+" (`:319-322`).
- **Sprint 025 rules** (`docs/sprints/sprint-025-CL.md:11,38,41,50`): Escape cancels and Enter saves in every inline editor; invalid time blur stays open; contract select autofocuses; Delete visible on touch/focus; first Tab lands in the sidebar. **Sprint 030 (A-11)** (`sprint-030-CL.md:48,50`): after save focus the saved card (`tabindex=-1`, `data-entry-id`) else the day's "+" (`entry-focus.ts:17-33`), only when focus is on `<body>` or inside the timesheet (`TimeEntriesPanel.svelte:304-310`); editors closed by keyboard return focus to their control (`TimeEntryCard.svelte:116-120`).

### 5. Timer-saved entries and offline outbox

- Sprint 019: the timer widget / Add Entry modal dispatch `time-entry-saved` on `window` (`weekly/time-entry-events.ts:7-24`); the panel refreshes, loads that entry's week if needed and focuses its card (`TimeEntriesPanel.svelte:325-332,384`). No reload. The timer also calls `navigation.showTimeEntryDay(savedDate)` (`timer/TimerWidget.svelte:382-383,416-417`), so the timesheet switches to that week, scrolls the day to the top and highlights it.
- Offline: `OfflineDataService` serves weeks from the read cache and **projects queued creates/edits/deletes onto them** (`offline/offline-data-service.ts:318-328`); creates/edits/deletes queue on network failure with temp IDs (`:330-406`). The panel refreshes on `OUTBOX_REPLAYED_EVENT`/`OUTBOX_RESOLVED_EVENT` (`TimeEntriesPanel.svelte:381,385-386`). Cards show `OutboxMarker` by real or temp ID (`TimeEntryCard.svelte:368-370`). Queued entries have `clientColorIndex` 0 and empty names unless the contract cache supplies them (`offline-data-service.ts:343-359`). Week status is not queued.

## (c) Open items

**O04 (divider endpoints). Recommendation:** keep it open, but build the row as a CSS grid with a fixed identity column (mark + contract name) and a content column, and draw each entry's separator as a `border-top` on the content column only (starting at the left edge of the client/contract name column, running to the right content edge). That matches the owner's quote ("collapse to the left of the client name"), makes same-client separators line up for free, and is a one-line change if the review moves the start point. Prototype at desktop and 390px before sign-off; do not add vertical rules.

**O05 (week numbering). Facts:** today every label, the URL, `/api/me`, the CLI and the status table key use ISO week-year + week. **Worked examples (Monday-start weeks):**

| Week (Mon-Sun) | Current code (ISO) | Calendar-year start, "week containing 1 Jan is week 1" |
| --- | --- | --- |
| 29 Dec 2025-4 Jan 2026 | 2026 W1 | 2026 W1 |
| 2-8 Nov 2026 (today) | 2026 W45 | 2026 W45 |
| 21-27 Dec 2026 | 2026 W52 (▶ label wrongly says "Week 1") | 2026 W52 |
| 28 Dec 2026-3 Jan 2027 | **2026 W53** | **2027 W1** |
| 4-10 Jan 2027 | 2027 W1 (◀ label wrongly says "Week 52") | 2027 W2 |
| 27 Dec 2027-2 Jan 2028 | 2027 W52 | 2028 W1 |
| 3-9 Jan 2028 | 2028 W1 | 2028 W2 |

The two conventions agree for all of 2026 and diverge from 28 Dec 2026, i.e. in about seven weeks. A third option, splitting 28-31 Dec (2026 W53, 4 days) from 1-3 Jan (2027 W1, 3 days), creates true partial weeks but breaks the Mon-Sun week as the unit of status and totals; not recommended.
**Recommendation:** (1) get the owner to confirm "the Mon-Sun week containing 1 January is week 1 of that year" (or name another rule) before December; (2) make the Monday date the canonical week identity everywhere internally (the status table already stores `week_start`; key lookups on it and keep year/week as derived display columns, with a migration that recomputes them); (3) put the label rule in one function used by WeekStrip, older-week headings, tab title and history labels, and derive prev/next labels from shifted dates; (4) decide separately whether URLs/CLI keep ISO `2026-W53` keys (stable machine format) or change, since the CLI and the secretary skill use them; (5) add unit tests for the table above. Fix the 52/53 label arithmetic regardless.

**O11 (edit semantics). Recommendation:** keep the current, already-shipped semantics as the engineering decision and document them: Enter commits, Escape cancels, blur commits valid text for description and time, selects commit on change, Done/Enter/Escape close the deliverable pair, focus returns to the field's control, errors on the card. These come from sprints 025/030 and are covered by tests; the spec forbids inventing a new policy. Targeted changes within TR-06: render the DurationField preview/error in reserved space or as an overlay so rows do not grow; switch the description editor to an auto-growing textarea that still treats Enter as commit; keep the value in the editor on a failed save so the user can retry; replace nested `<button>` links with a non-button description trigger. Explicitly out of scope: adding 409 version checks to entry PUT (raise with O10 if wanted).

## (d) Risks and things that must not break

- **Week identity change ripples:** `weekly_statuses` unique key (year, week_number), `/time/YYYY-Www` URLs and saved history, `/api/me.isoWeek`, CLI `parseIsoWeek` and the `chronolog-secretary` skill. Existing status rows from 2026 are correct under both conventions; 2026 W53 is the first row that would need remapping.
- **Sticky headings inside the scroller** will change `scrollDayToTop` and `rememberScroll` maths (`TimeEntriesPanel.svelte:42-50,64-85,107-113`) and the `max-height:500px` static-strip rule; keep `scrollTop`, not `scrollIntoView` (first-Tab rule).
- Keep `data-testid="time-entry-card"`, `data-entry-id`, `data-add-entry`, `data-testid="timesheet-scroll"`, `week-today-button`, `formerly-line`, `contract-change-notice`, the `.sticky.top-0` week strip (`navigation-journeys.spec.ts:303`; `iphone-journeys.spec.ts:265`), and the card's `tabindex=-1`/`role=group` focus target.
- Contract change must keep clearing deliverable and work type (server does not); deliverable change must clear work type.
- `refreshWeeks` refetches every loaded week after each edit; a redesign that adds per-field optimistic state must not double-render or lose outbox projections.
- Wiki-link click must not also open the description editor (`stopPropagation`, `WikiLinkRenderer.svelte:11`).
