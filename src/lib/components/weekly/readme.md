# Weekly Time Entry Components

Components for displaying and editing time entries, used by the layout panels.

## Components

- **WeekStrip.svelte** — Week overview (057-DR, TR-01), sticky above the timesheet scroller (`data-testid="week-strip"`): ‹ › (titles name the neighbouring week numbers, no wrap at 52), "Week 45 · 2–8 Nov 2026", Today (041-CL), week total and status in one row (phone: total and status on one row below the days). Seven day cells: "Mon 2", duration, a thin segmented client-colour bar from the actual entries (`flex-grow` by share). A cell scrolls to that day's heading; it is not a filter. Today's cell keeps `bg-ochre-100`. A failed status save shows under the status (`statusError`).
- **TotalTimeModal.svelte** — Total time (sprint 065-TT; approved r1 layout since 066-TR, spec `docs/design/total-time-r1`), opened from the week total (WeekStrip's total is a button, `data-testid="week-total"`, title "Total time") and from an older week's total in TimeEntriesPanel (`older-week-total`). Owns the state: range (default the viewed week), the selection (every contract ticked on open, inactive, archived and the system Deleted Contract included, so the total equals the week total; always sent as contract IDs), the breakdown and hidden-contracts disclosures, and the sheet. The total follows through `TotalTimeQuery` (`total-time-query.svelte.ts`: 200 ms debounce, stale replies ignored, "…" while loading, never the previous number, `retry()`). Online only: "Needs a connection" offline, with Try again. Desktop (`md`+, `MediaQuery('(min-width: 48rem)')`): a centred modal bounded at 64rem × 46rem with margins, the bark header (title, Close), the date toolbar, then two columns with a quiet rule: the result left, `TotalTimeContractsPanel` right, each scrolling inside. Phone: full window sized to the visual viewport; presets, dates, `TotalTimeContractsRow`, the result; the page scrolls; the sheet opens over it. The contract list is drawn in exactly one place for the width, so a resize never doubles it (note: AppShell remounts the timesheet, and so closes the modal, when crossing 768 px). Escape closes the sheet first, then the modal; a backdrop click and Close close; focus returns to the opener (passed in, since WebKit never focuses a clicked button). Test ids: `total-time-modal`, `total-time-value`, `total-time-entry-count`, `total-time-message`, `total-time-retry`, `total-time-from` / `-to`, `total-time-preset-<key>`, `total-time-select-all` / `-none`, `total-time-selected-count`, `total-time-contract-<id>`, `total-time-row`, `total-time-breakdown-toggle`, `total-time-contracts-panel`, `total-time-contracts-row`, `total-time-contract-sheet`, `total-time-sheet-done`.
- **TotalTimeDateToolbar.svelte** — Quick ranges (the viewed "Week N" first when it is not the current week, then This week, This month, This year, All time; the matching one pressed in pine) and the labelled From / To native date inputs. Desktop one row with a rule below; phone the preset row, then From / To side by side. From after To marks both fields (`aria-invalid`), values kept.
- **TotalTimeContractsPanel.svelte** — Desktop Contracts column: heading, "N selected" (ticked IDs), All | None top right, the list scrolling inside.
- **TotalTimeContractsRow.svelte** — Phone "Contracts · N selected" row (filter icon, chevron) that opens the sheet; focus returns to it.
- **TotalTimeContractSheet.svelte** — Phone contract sheet over the dimmed results: Contracts with All | None, the list scrolling, an anchored footer with "N selected" and Done (bottom safe area). Live selection: Done, a backdrop tap and Escape only close it.
- **TotalTimeBulkActions.svelte** — All | None text actions (same scope as 065-TT: All ticks every listed contract).
- **TotalTimeContractList.svelte** — The shared contract checkboxes (`getContractsByClient({ includeSystem: true })`), in the desktop column and the sheet: client groups in the client's wash (`getClientBgClass`, heading `getClientWashTextClass`), rows of ContractMark, name (wraps) and a pine (`accent-color`) checkbox at the far right, the whole row the label; a ticked row is a surface punch-out within the tint. Inactive, archived and deleted contracts, each marked, under one collapsed toggle naming the kinds present ("Show inactive, archived and deleted (N)"); closing it never unticks.
- **TotalTimeResult.svelte** — The result: big pine total, entry count, then "By contract" open by default (a button disclosure; once toggled it stays as set across new totals), rows of ContractMark, contract name, client beneath, time right-aligned (most first, only contracts with time; desktop rows scroll under the total). States: "–" + "No contracts selected", "0h" + "0 entries" + "No time recorded", "–" + "From is after To", "Needs a connection" / "Couldn't load the total" with Try again.
- **total-time.ts** — Pure helpers for the modal: `rangePresets`, `matchingPresetKey`, `isRangeBackwards`, `selectedCountLabel`, `colorIndexByContract`, `orderContractsForPicker`, `contractStatusLabel`, `hiddenToggleLabel`, `contractsForRequest`, `totalDisplay` (which state the result shows), `isConnectionFailure`. Tested; `total-time-query.svelte.ts` (the request loop) is tested in `total-time-query.test.ts`.
- **WeekStatusMenu.svelte** — Menu for the week status: Unsubmitted, Draft ready, Submitted. Recordkeeping only; the Submitted hint says nothing is sent.
- **week-labels.ts** — Week heading, week span ("28 Dec 2026 – 3 Jan 2027"), neighbouring week numbers, day headings ("Thursday, 5 November"), strip day ("Mon 2"). Tested.
- **day-jump.ts** — `dayJumpScrollTop`: where to scroll so a day's heading sits under the week controls (replaces the fixed 8px offset). Tested.
- **missing-detail.ts** — `missingDetailFor`: the local "Add deliverable" / "Add work type" cue whenever the contract (or deliverable) has options and the field is empty (TR-05). Tested. **work-type-options.ts** caches "does this deliverable have work types?".
- **week-strip-segments.ts** — Pure helper for WeekStrip's per-day colour bar: aggregates minutes per client into one segment per client (keyed by `clientId`, ordered by first appearance). Unit-tested in `week-strip-segments.test.ts`.
- **TimerIndicator.svelte** — The app bar's reflection of the capture (sprint 053-DR, SH-04), shown only when AppShell's `reflection` says no timer widget is on screen. The capture's own identity (ContractMark, contract first, client under it; never the browsed contract). Running: the clock (ticking from the shared start, so it keeps time with no widget mounted), which is the running feedback (no running light since 064-DR). Stopped: "Finish entry" and the frozen duration. `data-testid="timer-indicator"`, `data-state="running|finish"`. With no capture and the desktop sidebar hidden it keeps the old "Timer" access (`timer-indicator-collapsed`). Reads from the shared `timer-state` store.
- **TimeEntryCard.svelte** — One entry row (057-DR, TR-03..TR-06). Grid: identity (ContractMark `sm` + contract name, client smaller beneath; stable `--size-entry-identity` column), description with "Formerly" lines and the classification (deliverable > work type, or the missing-detail cue) beneath, right-aligned duration and time range (none invented for a duration-only entry), then Delete / Attach note / outbox marker in a one-button-wide column (`--size-entry-action`, 2rem on touch). A container query on the day's list reflows it on a narrow panel: identity, the row actions and the time on one line (actions before the time, 064-DR, so the time ends at the row's right edge), description full width beneath; the narrow time column is at least 5.5rem so the actions line up row to row. Durations and ranges end exactly under the day heading's total at both widths (064-DR, T2; TimeEntriesPanel's heading padding mirrors the card's columns). Separators start at the contract name's left edge (`--spacing-entry-rule-start`, one token for the owner's layout review, O04) and run to the right edge. No background wash. Inline editing (settled semantics kept): click a field to edit, Enter saves, Escape cancels, blur saves description and time, selects save on pick (the deliverable / work type pickers are `EntryClassificationEditor`), focus returns to the field. The row keeps its height while editing: the description editor is a textarea that grows to the text (`WikiLinkInput multiline`), the classification line and time column reserve their editor heights, the time preview / error line sits in reserved space, the contract-change notice is one truncated line. A failed description or time save reopens the editor with the typed value. Other behaviour unchanged: wiki links, Show more, contract change clears the deliverable chain with a notice, Attach note (049-UI), `tabindex=-1` + `data-entry-id` for focus after save.
- **AttachNoteButton.svelte** — The card's "Attach note" icon button (sprint 049-UI): tooltip, `aria-disabled` with the reason as tooltip when the entry has no contract, and one note per click (a press while one is running is ignored).
- **attach-note.ts** — `appendWikiLinkToDescription` (adds `[[NOTE_ID]]` after a space at the end of the text, before any "Formerly" lines; no duplicate), `attachNoteBlockedReason`, and `attachNewNoteToEntry` (an empty note on the entry's contract through the data service, then the entry saved with the link, so offline both go through the outbox). Tested.
- **EntryClassificationEditor.svelte** — The card's inline deliverable / work type pickers on stage 4's shared `OntologyCascade` + `CascadeSelect` (checkpoint B/C): both levels always drawn, "Not applicable", failed load with Retry, sole work type taken on a deliverable pick. Opens on the entry's values with empty levels as explicit "none" (opening never picks); each pick is saved after the cascade settles; Done / Enter / Escape closes.
- **NewEntryRow.svelte** — Inline form (explicit Save / Cancel, unchanged in 057-DR) for adding a time entry, matching TimeEntryCard. Contract, deliverable and work type on the shared cascade (`CascadeSelect` per level; all three always drawn; Save waits for the cascade to settle), plus a time input supporting duration and range formats. Inline errors: "Pick a contract", the parser hint, and "Couldn't save". On phone the contract sits on its own row.
- **WikiLinkRenderer.svelte** — Renders `[[NOTE_ID]]` patterns as clickable inline link spans. Used in TimeEntryCard read mode.
- **WikiLinkInput.svelte** — Text input (or, with `multiline`, a textarea that grows to its text) with `[[` autocomplete for notes through the shared picker (checkpoint B/C): `search/LinkPicker` rows with mark and client / contract, `createLinkPickerSearch` (recent notes on a bare `[[`, debounce, stale replies ignored, Enter while loading inserts from the current reply), placed by `placeLinkPicker` in a fixed layer on `<body>` (above a phone keyboard). Keeps its own token detection and plain `[[ID]]` insertion; Escape closes the list and keeps the text. Used by TimeEntryCard (multiline) and NewEntryRow. Focuses on mount through an effect rather than the autofocus attribute.
- **formerly-lines.ts** — `splitFormerlyLines(description)` separates the "Formerly: …" lines (from `appendFormerlyLine`) from the description. Tested.
- **entry-focus.ts** — `focusSavedEntry(root, entryId, date)`: focus the saved entry's card, else the day's "+" (`data-add-entry`). Used by TimeEntriesPanel after a save. Tested.
- **time-entry-events.ts** — `time-entry-saved` window event (constant, dispatch and read helpers) used by the sidebar TimerWidget / Add Entry modal to tell TimeEntriesPanel to refresh its loaded weeks.

## Data Flow

Components receive data as props from the parent layout panel (`TimeEntriesPanel`). Mutations (create, update, delete) go through the `DataService` from context within each component, with `onUpdated`/`onEntryCreated` callbacks to trigger parent re-fetches.

TimeEntriesPanel (in `components/layout`) shows all seven days of the selected week, future days included, each under a bark-brown heading bar (date, local Add entry, day total; square ends; edge to edge of the scroller since 064-DR, its text in place and the total over the entries' durations) that is sticky inside its own day section, so the next day's heading replaces it at the boundary. Days with no entries get a quieter bar; today an ochre marker and "Today" tag, with no tint over the day. Older weeks are appended under "Show the week before". Phone: no footer timer bar (the header pill from 053-DR shows a running or stopped capture); since 060-DR the week controls have no Start timer or Add Entry: a new timer starts from the home screen's widget, and each day heading keeps its Add entry.
